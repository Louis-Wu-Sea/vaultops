# Contributing to VaultOps

Thank you for your interest in contributing to VaultOps! This guide will help you get started.

## Development Setup

### Prerequisites

- **Node.js** >= 18
- **Obsidian** (recommended, for viewing vault output)
- **Claude Code** (for testing skills and MCP tools)

### Getting Started

```bash
git clone https://github.com/Louis-Wu-Sea/vaultops.git
cd vaultops
npm install        # install dev dependencies (typescript, tsx, @types/node)
npx tsc            # compile TypeScript → scripts/compiled/

# Verify tool count (43 tools)
node -e "const {listTools}=require('./scripts/compiled/tools/index.js');console.log(listTools().tools.length,'tools')"

# Run tests
npm test

# Test CLI
node scripts/vault_cli.js --help
```

## Architecture

```
src/                          # TypeScript source
  index.ts                    # MCP server entry point (stdio JSON-RPC 2.0)
  tools/                      # 43 tool handlers (11 modules)
  hooks/                      # 6 Claude Code hooks + shared brain-state
  fs/                         # File system utilities
  vault/                      # Vault resolution + registry
scripts/
  compiled/                   # Compiled JS output (generated by tsc)
  vault_cli.js                # CLI (Node.js, stdlib only — no npm deps)
  cli/dashboard/              # TUI dashboard components
skills/                       # Slash command definitions (SKILL.md files)
install.sh                    # One-command installer
```

### Key Constraints

- **MCP server + hooks**: TypeScript, compiled to JS, Node.js stdlib only (zero runtime npm deps).
- **CLI**: Node.js stdlib only. No `npm install` dependencies at runtime.
- **Dev dependencies**: `typescript`, `tsx`, `@types/node` only.
- **Data format**: Obsidian-compatible markdown with YAML frontmatter.
- **Links**: Wiki-links (`[[EXE-001]]`) for task relationships.
- **Diagrams**: Mermaid in markdown (Obsidian renders natively).

## How to Contribute

### Reporting Bugs

1. Check [existing issues](https://github.com/Louis-Wu-Sea/vaultops/issues) first
2. Use the bug report template when creating a new issue
3. Include your Node.js version and OS

### Adding a New MCP Tool

1. Add the tool handler in `src/tools/<module>.ts`
2. Register it in `src/tools/index.ts` (handler map + schema definition)
3. Follow the existing patterns for input schema and error handling
4. Run `npx tsc --noEmit` to type-check
5. Update `CLAUDE.md` with the new tool documentation
6. Test with Claude Code: verify the tool appears and works

### Adding a New Skill

1. Create `skills/<skill-name>/SKILL.md`
2. Include frontmatter with `description`, `filePattern`, and `bashPattern`
3. Write the skill prompt in the body
4. Test with Claude Code: `/vault:<skill-name>`

### Code Style

- **TypeScript**: Strict mode, use explicit types. Follow existing patterns in `src/`.
- **JavaScript** (CLI): Single quotes preferred.
- **Markdown**: Use YAML frontmatter for structured data. Keep files Obsidian-friendly.

## Pull Request Process

1. Fork the repository
2. Create a feature branch: `git checkout -b feat/my-feature`
3. Make your changes
4. Verify: MCP server loads, CLI runs, tool count is correct
5. Open a PR with a clear description of what and why

### Branch Naming

- `feat/` — new features
- `fix/` — bug fixes
- `docs/` — documentation changes
- `refactor/` — code restructuring

### Commit Messages

Use conventional commits:

```
feat: add sprint velocity chart tool
fix: handle missing vault root gracefully
docs: update MCP tool reference
```
